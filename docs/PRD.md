## 0. 원문 상태

- 1차 근거는 사용자가 저장한 **브라우저 캡처 텍스트**다 ("Retrieved: 2026-11-10 (page text captured via browser; tables converted to plain text)").
- 공식 PDF 원문은 WebFetch에서 HTTP 403으로 열리지 않았다. 캡처본의 진위와 최신성은 **[확인 필요]** (7절 9번).
- 캡처본에 명시된 규칙은 "원문 확인"으로 표기하고 절 제목을 인용한다.
- 캡처본에 없는 것 (추첨제 발표, Form 1464, 정상 근무일 기준 등)은 "사용자 제공" 또는 "확인 필요"로 표기한다.
- 원문 예시 Karla의 61일은 식 `근무일 × 7 ÷ W`에 기간 평균 근무일 43.57일을 넣으면 재현된다 (4.2.4 검산 참고 위치는 6절).

## 1. 목표

- 한국인 워킹홀리데이(Subclass 417) 메이커가 세컨 비자(88 달력일)와 서드 비자(179 달력일)에 필요한 인정 근무를 기록하고 추적한다.
- 근무지 포스트코드와 업무 유형으로 세컨 인정 지역 여부를 미리 확인한다.
- 페이슬립에서 필요한 정보만 골라 기록하고, 신청 시 참고할 근무 이력 PDF를 만든다.
- **실제 공개 배포**를 목표로 한다 (v4). 비용은 가능한 한 0원으로 하고, 유료가 필요하면 사용자 승인 후 진행한다. 호스팅 후보는 `docs/decisions/hosting.md`에 비교만 있고 결정은 아직 없다.
- 백엔드 포트폴리오 목적. Java 17, Spring Boot, JPA, MySQL, Thymeleaf 서버 렌더링, Spring Security.

## 2. 범위 / 비범위

### 범위 (MVP 기능 5개)

| 번호 | 기능 | 요약 |
|---|---|---|
| F1 | 근무 기록과 인정 일수 계산 | 매일 출근하는 정규 근무 기간, 또는 일한 날 기록 (날짜별 여러 근무), 같은 날 1일 |
| F2 | 세컨 인정 지역·업무 확인 | 시드 CSV(state 우선)와 번호대 표 기준 판정, 업무 유형 판정 |
| F3 | 페이슬립 가져오기와 증빙 체크리스트 | 브라우저에서 읽고 추출 값만 전송. 원본은 서버로 보내지 않음 |
| F4 | 근무 이력 PDF 내보내기 | 고용주별 요약과 상세 표 (영문) |
| F5 | 1년차 만료일 기준 남은 기간·페이스 | 남은 기간, 필요 일수, 배너 알림 |

### 비범위

- Subclass 462 규칙 (화면에 "462는 아직 지원하지 않아요" 안내만 표시).
- 페이슬립 OCR 자동 인식 (유료 API 제외).
- 페이슬립 원본 파일의 서버 저장 (v4 결정으로 폐기).
- 이메일·비밀번호 가입 (MVP 제외, 나중 검토).
- 88일 착수 기한 역산 계산.
- 데이터 전체 백업 JSON 내보내기 (F4 PDF 출력은 포함).

- 임금 체불 대리, 법적 분쟁 지원, 이민 자문.

## 3. 사용자 시나리오

- **A. 매일 출근하는 정규 근무**: 준호는 한 농장에서 매일 출근하는 계약으로 일한다. 시작일과 종료일을 **정규 근무 기간 1건**으로 등록한다. 주말은 자동 포함된다. 무급 날씨 휴무나 고용 공백 구간은 제외 구간으로 뺀다.
- **B. 일한 날만 기록**: 지은은 여러 고용주에서 일한다. 일한 **날짜마다** 근무를 등록한다. 한 날짜에 근무가 여러 개일 수 있고 (고용주 + 시간), 그 날은 몇 곳이든 1일이다.
- **C. 페이슬립으로 추가**: 지은은 페이슬립 PDF를 폰에서 고른다. 앱이 고용주, ABN, 급여 기간, 총 근무 시간을 폰 안에서 읽어 보여주고, 날짜만 직접 골라 저장한다. 원본 파일은 서버로 가지 않는다.
- **D. 구직 전 확인**: 민수는 포스트코드 4670 농장 오퍼를 받았다. 포스트코드와 업무 유형을 입력하면 세컨 인정 지역인지 확인하는 결과와 근거를 본다.
- **E. 신청 준비**: 지은은 홈 화면의 "N일 인정"이 목표에 가까워지면 PDF를 내려받아 신청에 참고한다.

## 4. 기능 상세

### 4.0 데이터와 저장

- 근무 기록은 **서버 DB**에 저장하며 회원 계정 단위로 분리한다.
- 서버에 저장하는 항목: 날짜, 근무 시간, 고용주명, 고용주 ABN (선택), 포스트코드, 업무 유형, 정상 근무 시간, 페이슬립 추출 값 (고용주명, ABN, 급여 기간, 총 근무 시간, 고용 형태 참고용).
- 페이슬립 PDF 원본은 서버로 보내지 않는다. 사용자 기기에만 남는다.
- 고용 형태 (풀타임, 캐주얼, 파트타임)는 **계산에 쓰지 않는다.** 메모용 표시로만 둔다.

### 4.1 고용주와 업무 등록

- 고용주마다 등록한다: 고용주명, 근무지 포스트코드 (숫자 4자리, 0000 불가), 정상 근무 시간 (시간/일, 0 초과 24 이하, 0.5시간 단위), 업무 유형, ABN (선택, 입력 시 체크섬 검증. 입력 검증이며 규정 요건이 아니다).
- 업무 유형 질문 (화면 문구):
  - "수확·포장 등 바로 하는 작업" → **인정**.
  - "소시지·와인 제조 등 가공품 제조" → **불인정** (원문 "Plant and animal cultivation" 절 secondary processing).
  - "일반 정원 관리" → **불인정** (원문 "Plant and animal cultivation" 절: general garden maintenance is not an eligible activity).
  - 농축산의 주 업무 여부 (원문 "This must be your primary employment task") 질문을 함께 둔다.
- 시안 참고: 직접 입력 화면의 일터 카드는 "수확"과 "과일 포장"을 업무 라벨로 쓴다. 등록 질문은 위 문구를 따른다 (7절 15번).
- 업무 유형은 F2 판정과 연결된다 (4.3).

### 4.2 F1 근무 기록과 인정 일수

#### 4.2.1 두 가지 세는 방식

| 방식 | 내부 명칭 (개발 문서용) | 입력 | 계산 |
|---|---|---|---|
| 매일 출근하는 정규 근무 | 모드 A | 시작일, 종료일, 고용주 (제외 구간 0개 이상) | 기간 안 달력일 전부 (주말 포함), 제외 구간 뺌 |
| 일한 날만 기록 | 모드 B | 날짜별 근무 (날짜 1개에 근무 여러 개, 근무 = 고용주 + 시간) | 날짜별 판정 후 확실한 날만 환산 |

- 정규 근무 기간은 고용주의 정상 근무 시간을 등록해야 저장된다. 정규 근무는 시간 판정을 하지 않는다 (7절 1번).
- 일한 날 기록은 날짜당 한 행이며, 한 행 안에 근무가 여러 개 들어간다. 날짜를 두 번 저장하지 않는다.

#### 4.2.2 같은 날 규칙

- 같은 날짜는 고용주가 몇 곳이든 **1일을 넘지 않는다** (원문 "Normal work days or shifts": "You cannot count work carried out on one calendar day as more than one day of specified work").
- 근무 시간은 날짜별로 합산하여 판정에 쓴다. 같은 날 합계가 24 시간을 넘으면 저장을 거부한다.

#### 4.2.3 하루 판정

각 날짜의 근무를 다음 기준으로 분류한다. 인정 지역과 인정 업무 여부는 F2 판정을 따른다.

1. **인정 지역·인정 업무이고, 근무 하나가 그 고용주의 정상 근무 시간 이상** → **확실**.
2. **인정 지역·인정 업무이지만 모든 근무가 정상 시간보다 짧음** → **짧게 일한 날 (인정 안 될 수도 있어요)**.
3. **여러 고용주의 시간을 합쳐야 정상 시간이 되는 날** → **짧게 일한 날**과 같은 분류 (결정 2026-11-10).
4. **인정 지역이 아니거나 인정 업무가 아닌 근무**는 판정에서 제외한다. 그 시간은 날짜에 포함되지 않는다.

날짜 단위 결과:
- 확실 날짜 = 1일로 센다.
- 짧게 일한 날 = 인정 일수에서 뺀다. 개수만 별도로 표시한다.
- 제외된 근무만 있는 날짜는 셈에서 빼고, 표시도 하지 않는다.

#### 4.2.4 인정 일수 계산 (내부 계산, 화면에는 "N일 인정"으로만 표시)

- 차수별 인정 일수 = 정규 근무 달력일 (확실 기간) + 일한 날 환산 일수 (확실 날짜).
- 일한 날 환산 일수 = 확실 날짜 수 × 7 ÷ W. **W는 정상 주당 근무일 수, 5로 고정한다** (결정 2026-11-10: 두 곳 합산 날 포함 W=5 고정).
  - W는 사용자가 임의로 바꿀 수 없다. 업종 표준 근거를 사유와 함께 기록하는 경우에만 변경을 허용한다 (결정 12). 기본 5의 원문 근거는 근거 불충분이며, 제품 결정으로 고정했다 (7절 1번 해결 기록, 12절).
  - 각 날짜 행은 저장 시점의 W를 스냅샷으로 가진다. 기준값 변경 이력은 변경 시각, 이전 값, 새 값, 사유와 근거 출처를 남긴다.
- 검산 (원문 Karla 예시, 식 유지): 122 달력일 기간 (2027-08-01 ~ 2027-11-30 가정), 주 5일 중 2주에 5일 (절반). 기간 평균 근무일 122 × 5 ÷ 14 = 43.57일. 43.57 × 7 ÷ 5 = **61.0** (원문 61과 일치). 정수 근무일 입력 (43일 → 60.2, 44일 → 61.6)은 근사 오차로 표기한다.
- 반올림 (내부 계산): 행별 원값 보관, 누적 합계는 원값을 더한 뒤 반올림. 표시는 소수 첫째 자리 half-up.
- 화면 표시 (홈): **확실한 일수의 합을 정수로 내림**하여 "N일 인정"으로 표시한다. 소수점은 상세 화면에서만 보여준다 (입력 화면 숫자의 표시 방식은 7절 15번).
- 짧게 일한 날은 홈에서 별도 개수로 보여준다. 인정 일수 합계에는 넣지 않는다.

#### 4.2.5 차수 귀속 (원문 규칙, 변경 없음)

- 세컨 비자 88 달력일: 1차 워킹홀리데이 비자 보유 중 근무 (원문 "Circumstances in which specified work must have been undertaken").
- 서드 비자 179 달력일: 2차 워킹홀리데이 비자 보유 중 근무이며 **2019-07-01 이후** 근무분.
- 학생 비자 등 다른 비자 중 근무: 불인정.
- 서드 신청에서 1차 비자 중 근무: 불인정.
- 2019-06-30 이전 근무 (서드): 불인정.
- 근무 날짜가 해당 차수 비자 기간에 속하면 그 차수에 집계. 비자 기간 시작·종료일은 사용자 입력. 기본 배정은 근무 날짜 기준이며 사용자가 수정할 수 있다 (결정 9).
- 브리징 비자 예외는 상세 조건 [확인 필요] (7절 2번). MVP는 브리징 기간에 "브리징 비자 중" 표시를 하고, 경고와 함께 집계한다.

#### 4.2.6 진행과 신청 가능 조건

- 진행 표시: 차수별 "N일 인정 / 88일" (또는 179일). 100% 이상은 "목표 달성".
- **"시작한 지 3개월(88일)이 지나야 신청할 수 있어요"**: 첫 인정일부터 마지막 인정일까지 양끝 포함 달력일 수 (span)가 88 이상이어야 한다. 원문 근거: "Minimum period" 절, "You cannot complete the specified work requirement in a total period shorter than 3 or 6 calendar months." 서드 문구는 14번.
- 두 조건 모두 충족해야 "신청 조건 충족 가능"으로 표시한다: (1) 인정 일수 ≥ 목표, (2) span ≥ 목표.

#### 4.2.7 제외와 특수 규칙

- 무급 날씨 휴무: 인정 제외 (원문 "Severe or seasonal weather").
- 유급 공휴일, 유급 병가 (보상휴가 포함): 인정 (원문 "Australian public holidays and sick days").
- 교대근무: 업종 표준이면 로스터 휴무 포함 인정. **계약 기간 전체에 급여가 지급되어야 한다** (원문 "Shift work"). 계약서 사본 보관 권고.
- 재해 복구 업무 (자원봉사 포함): 저장은 가능. 기본은 인정 일수에서 제외. 화면 안내 "재해 복구 업무, 계산 제외 [확인 필요]". 봉사 근무일은 1일 (원문 "Normal work days or shifts").
- 피스레이트: 원문 인정 (Karla, Jian 예시). 고용 형태는 메모용이다. 인정 여부는 근무 방식 (정규 또는 일한 날)과 업무 유형으로 판정한다.
- 기록 기간 cap: 일한 날 기록의 환산 합계는 그 기록 기간의 달력일 수를 넘을 수 없다. 초과하면 기간 달력일로 cap하고 경고를 표시한다.

#### 4.2.8 F2 판정 연결

- 확실 또는 짧게 일한 날 분류는 F2에서 "세컨 인정 지역 + 인정 업무"인 근무에만 적용한다.
- F2 결과가 "확인 불가"인 근무는 판정에서 제외하고 "미인정 가능 근무" 목록에 따로 보여준다.
- F2 "조건부" (예: 관광 지역 신청 시점 조건, 재해 복구 신청 유형 미선택)는 사용자가 조건 충족을 체크한 경우만 포함한다.
- 판정 결과는 저장 시점의 스냅샷으로 남긴다. 시드가 바뀌면 재계산 버튼으로 갱신한다.

#### 4.2.9 예외 (저장 거부)

- 근무 시간 0 이하 또는 24 초과.
- 같은 날 근무 시간 합계 24 초과.
- 종료일 < 시작일, 제외 구간이 기간 밖이거나 서로 겹침.
- 정상 근무 시간 미등록 (정규 근무 기간 저장 시).
- W가 1~7 정수가 아님 (현재 W는 5 고정이므로 사용자 입력 경로는 없다).
- 미래 날짜: 경고 후 저장 허용.

### F2. 세컨 인정 지역·업무 확인

#### 4.3 입력

- 포스트코드 (4자리). 주 (state)는 4.3a 규칙으로 판별.
- 업무 유형:
  - 관광·요식업 (표 1~3): 세부 업무 (숙박, 음식·음료, 관광객 대상 서비스) 필수.
  - 농축산·어업·임업·광업·건설 (표 4): 농축산이면 주 업무 여부와 작업 종류 (수확·포장 / 가공품 제조 / 정원 관리)를 입력.
  - 산불 복구 (표 5).
  - 재해 복구 (표 6): 신청 유형 ("flood recovery - paid" 또는 "flood recovery - volunteer") 선택.
  - 코로나 의료 (표 없음, 전국, 2020-01-31 이후 근무): 원문 "Critical COVID-19 work in the healthcare and medical sectors" 절. 시드 CSV에 없으며 F2 규칙으로만 처리한다.
- 신청 예정일: 관광 (표 1~3)과 재해 복구 (표 6)의 날짜 조건 확인에 쓴다.

#### 4.3a 포스트코드 → 주 판별 (승인 결정 반영)

1. **시드 CSV의 `state`를 우선한다** (결정 2026-11-10). 포스트코드가 CSV에 있으면 그 행의 `state`를 쓴다.
2. 한 포스트코드에 CSV 행이 여러 주로 있으면 (예: 0872: WA·SA) 해당 주들을 모두 후보로 보여주고 사용자가 고르게 한다 (7절 19번).
3. CSV에 없는 포스트코드에만 아래 번호대 표를 쓴다.

- 번호대 표 기준: 호주 우편번호 번호대 체계 (공식 원문 아님, 조사일 2026-11-10 표기).

| 주 | 포스트코드 번호대 |
|---|---|
| NT | 0800–0999 |
| SA | 5000–5799, 5800–5999 |
| TAS | 7000–7799, 7800–7999 |
| ACT | 2600–2618, 2900–2920 |
| NSW | 1000–1999, 2000–2599, 2619–2899, 2921–2999 |
| VIC | 3000–3999, 8000–8999 |
| QLD | 4000–4999, 9000–9999 |
| WA | 6000–6797, 6800–6999 |

- **2899 Norfolk Island (결정 2026-11-10)**: 원문 Table 1에 따라 **NSW**로 처리한다. 시드의 Norfolk Island 행 (ALL)은 NSW 주 판별로 매칭하지 않고, 원문 표 기재 그대로 "Norfolk Island" 행으로 보존한다 [확인 필요는 해결됨].
- 대조 결과 (2026-11-10)의 14개 불일치는 시드 CSV `state` 우선 결정으로 해결됨 (12절). 불일치 목록: 0872, 2611, 2618, 2640, 2641, 3644, 3707, 4375, 4377, 4380, 4383, 4385, 6798, 6799.
- 표 기준에 공백이 있는 번호 (6798–6799)는 CSV 행이 있을 때만 판정하며, CSV에 없으면 "확인 불가"로 표시한다.

#### 4.4 판정 로직

- 판정 대상: 시드의 `postcode`, `industry`, `table`, `condition`.
- `postcode = "ALL"` 행: 해당 주 전체에 일치한다 (시드 규칙).
- 일치 행이 있으면: **"세컨 인정 지역 (목록 기준)"**과 시드 `condition` 문장을 함께 표시한다.
  - `condition`에 신청 날짜 조건이 있으면 신청 예정일로 확인하고, 만족하지 않으면 "조건 미충족"으로 바꾼다.
  - 재해 복구는 신청 유형이 남아 있으면 "조건부"로 표시한다.
- 일치 행이 없으면: **"확인 불가 (목록 기준 해당 없음)"**. 근거 문장으로 원문 "Approved industries and areas for specified work" 절의 유연성 조항을 표시한다. 행정·청소 업무는 산업을 지원하면 인정될 수 있다고 원문에 있다 (판단 기준 [확인 필요], 7절 4번).
- 목록 밖은 항상 "확인 불가"다.
- 작업 유형 제외: 원문이 인정 업무가 아니라고 정한 작업 (농축산의 가공품 제조, 일반 정원 관리)은 "인정 업무 아님 (작업 유형)"으로 표시한다. 목록 판정이 아니라 작업 유형 판정이다. 농축산의 주 업무 여부는 사용자가 확인한다.
- 근거 표시: `source_url` (`https://immi.homeaffairs.gov.au/visas/getting-a-visa/visa-listing/work-holiday-417/specified-work`), `retrieved_at` 2026-11-10, `verify_status` `captured_from_official_page`.
- 노후 경고: 조사일로부터 90일 경과 시 "목록 재확인 필요". 90일은 가정값이며 원문 변경 주기는 확인되지 않았다 [확인 필요] (7절 9번과 연결).

#### 4.5 시드 파일

- 경로: `docs/seed/specified_work_postcodes.csv` (개발 단계에서 `src/main/resources/seed/specified_work_postcodes.csv`로 복사). CSV는 수정하지 않는다.
- 열: `postcode, state, industry, table, condition, source_url, retrieved_at, verify_status`.
- 행 수: 5,765행. 고유 포스트코드 3,136개 (ALL 포함), ALL 제외 3,135개.
- 외부 API를 호출하지 않는다.
- 1단계: 시드를 classpath 리소스로 읽는다. 시드 DB 테이블은 2단계.

### F3. 페이슬립 가져오기와 증빙 체크리스트

#### 4.6 흐름

1. 사용자가 페이슬립 PDF를 고른다. 파일은 **브라우저 안에서만** 읽는다 (pdf.js 등 클라이언트 라이브러리).
2. 브라우저가 고용주명, ABN, 급여 기간 (시작·종료), 총 근무 시간, 고용 형태 (참고용)를 추출해 확인 화면에 보여준다.
3. 사용자가 값을 확인하고 고치면, **추출 값만** 서버로 보낸다.
4. 서버는 추출 값을 근무 기록 또는 고용주 정보와 연결해 저장한다.
5. 원본 파일은 서버에 전송하지 않고, 저장하지 않는다. 사용자 기기에만 남는다.
6. 날짜 선택: 페이슬립에는 주간 합계만 있으므로 날짜는 사용자가 직접 골라 일한 날로 기록한다 (시안 "이번 주 일한 날을 골라주세요").

- 이미지 (JPG, PNG) 페이슬립: 브라우저 추출은 MVP 범위가 아니다. 수동 입력으로 대체한다 (7절 13번).
- 업로드 안내 (화면 문구, 4.8 시안 기준): "날짜·시간·일터만 읽어서 저장하는 데 동의해요 (TFN·계좌번호는 읽지 않아요)." 동의 체크가 저장 조건이다. 안내 문구: "계산에 필요한 내용(날짜·시간·일터)만 저장해요. 원본 파일은 서버로 보내지 않아요."
- v3까지의 서버 저장 디렉터리 (`storage/`), UUID 파일명, 매직 바이트 검증, 파일 응답 헤더, 삭제 순서와 고아 파일 처리는 **v4에서 삭제**했다.

#### 4.6.1 증빙 체크리스트 (사용자 O/X 자가 점검)

1. 고용주 상호명, ABN 일치
2. 피고용인 성명 (여권 영문명과 동일)
3. 급여 기간 명시
4. 시급 단가 (또는 피스레이트 단가), 총 근무 시간 명시
5. 세금 (PAYG) 공제 내역
6. 연금 (Superannuation) 적립 내역
7. 실입금액과 Net pay 일치

- 체크 결과는 서버에 항목별 값으로 저장한다. 완성도 점수 (예: 5 / 7)를 표시한다.
- 근거: "Overview" 절 "All specified subclass 417 work must be paid in accordance with the relevant Australian legislation and awards." 체크리스트 항목은 MVP 점검 항목이며 원문에 없다.
- 현금 지급 기록은 "인정 위험이 높을 수 있어요" 경고. 단정 표현 금지. 인정 여부는 원문에 명시되지 않음 [확인 필요] (7절 3번).

### F4. 근무 이력 PDF 내보내기

- 서버에서 생성한다. 라이브러리 OpenPDF (결정 6, 라이선스 [확인 필요] 7절 18번).
- 입력: 기간, 포함할 고용주. 페이슬립 부록은 포함하지 않는다 (원본을 서버에 두지 않으므로). 추출 값과 체크리스트 결과만 기재한다.
- 출력 (영문 PDF):
  - 헤더: 신청자 이름(영문), Subclass 417, 출력 일시.
  - 요약표: 차수별 인정 일수 (정규 근무 달력일과 일한 날 환산을 구분 표기), 확실 날짜 수, 짧게 일한 날 수 (별도 표기), 총 근무 시간, 고용주 수.
  - 상세표: 고용주 법적 명칭, ABN, 근무지 주소와 포스트코드, 기간, 인정 일수, 업무 유형, 근거 상태.
  - 근거 행: 사용한 규칙, 원문 절 제목, 출처 URL, 조사일.
  - 근거 상태 열 값: `원문 확인` / `사용자 제공` / `확인 필요`.
  - 푸터 면책 문구 병기:
    - 영문: "Not legal or migration advice. Check official Home Affairs guidance for the final decision."
    - 한국어: 법률·이민 자문이 아니며, 최종 판단은 호주 내무부 공식 안내를 확인하세요.
- PDF 영문 본문의 "specified work"는 이민성 제출용 공식 영문 용어이므로 유지한다 [확인 필요] (7절 17번).
- 예외: 인정 일수 0이면 "기록 부족" 워터마크. 미리보기 화면에도 면책 문구.

### F5. 1년차 만료일 기준 남은 기간과 페이스

- 입력:
  - 1년차 비자 만료일 (필수).
  - 완료 목표 버퍼 일수 (필수, 기본값 없음, 결정 3). 정수 0 이상. 음수와 소수는 입력 단계에서 거부.
- 정의:
  - 기준일은 1년차 비자 만료일이다 (마지노선 아님).
  - 완료 목표일 = 만료일 − 버퍼 일수. 사용자 목표이며 규정상 착수 기한이 아니다.
  - 버퍼 0이면 완료 목표일 = 만료일로 허용한다.
  - 완료 목표일이 오늘보다 앞이면 "목표 기간 경과" 표시 (저장은 허용).
  - 88일 착수 기한 역산은 MVP에서 제외 [확인 필요] (7절 6번).
- 계산 (내부):
  - 남은 달력일 R = 완료 목표일 − 오늘.
  - 세컨 목표 필요 일수 N = 88 − 현재 인정 일수 (최소 0).
  - 주당 필요량 = N ÷ R × 7, 소수 첫째 자리 half-up (상세 화면만 소수 표시).
  - R이 0이면 "계산할 수 없어요".
  - 기간 조건 점검: 완료 목표일 − 첫 인정일 + 1 < 88 이면 "시작한 지 3개월(88일)이 지나야 신청할 수 있어요" 경고.
- 화면: 남은 기간, 필요한 인정 일수 ("N일 인정 더 필요해요" [문구 확인 필요] 7절 15번), 주당 필요량, 기간 조건 경고, 면책 문구.
- 확인 수준: 88 달력일은 `원문 확인` (캡처본). 주당 필요량 계산은 `사용자 제공` (MVP 자체 계산). 근무일 정의는 `확인 필요` (7절 7번).
- 알림: 대시보드 배너. 완료 목표일 기준 D-120, D-90, D-60, D-30 시점에 노출 (결정 4). 앱 실행 시 계산. 푸시와 이메일은 없다.
- 예외:
  - 만료일 경과: "비자 만료일이 지났는지 확인해 주세요" 표시, 배너 대신.
  - 인정 일수 ≥ 88: "목표 달성" 메시지, 배너 대신 (기간 조건 경고는 계속 표시).

## 4.7 화면 용어 (결정 문서 3절, 화면 기준)

| 쓰지 않음 | 화면에서 사용 |
|---|---|
| specified work, 2년차/3년차 조건 | 세컨 비자 인정 근무, 서드 비자 |
| 환산일, 달력일, W | 숨김. "N일 인정"으로만 표시 |
| 모드 A / 모드 B, 풀타임/캐주얼 (계산 의미) | 매일 출근하는 정규 근무 / 일한 날만 기록 |
| 확인 필요 (짧은 날 분류) | 짧게 일한 날 – 인정 안 될 수도 있어요 |
| span, 기간 조건 | 시작한 지 3개월(88일)이 지나야 신청할 수 있어요 |
| 1차/2차 가공 | 수확·포장 = 인정 / 가공품 제조 = 불인정 |
| 포스트코드 인정 지역 | 세컨 인정 지역 |

## 10. 완료 기준 (MVP)

- 1단계 (11절): 인증 기반 (구글 로그인, CSRF), F1 (정규 근무, 일한 날 기록, 같은 날 규칙, 하루 판정, cap, 차수 귀속, 완료 조건), F2 (주 판별, 판정, ALL 행, 날짜 조건, 다중 주 표시), F5 (계산, 배너, 버퍼 검증). 각 기능이 끝나면 멈추고 보고.
- 2단계 (11절): F3 (브라우저 추출, 추출 값만 전송, 체크리스트), F4 (PDF). 각 기능이 끝나면 멈추고 보고.
- 배포 준비 (사용자 승인 후): 호스팅 결정, 개인정보 처리방침, 이용약관, HTTPS.

- 모든 계산 결과 화면에 면책 문구. 화면 용어는 4.7 표 기준.
- 스키마 작업은 승인된 범위만 (11절).
- CLAUDE.md는 배포 결정에 맞게 갱신 완료.

## 11. 구현 순서, 승인 조건, 구현 영향 (v4 승인 반영)

### 11.1 구현 순서

- **1단계**: 인증 기반 (구글 로그인, Spring Security, CSRF) → F1 → F2 → F5. 각 기능이 끝나면 멈추고 보고한다.
- **2단계**: F3 → F4. 각 기능이 끝나면 멈추고 보고한다.
- **배포 단계**: 호스팅 결정 (사용자), 처리방침, 약관.

### 11.2 Flyway (승인 반영)

- 배포 전이므로 v4 구조로 다시 써도 된다 (승인 결정 7). 로컬 MySQL에 이전 V1·V2가 적용돼 있으면 DB를 새로 만든다. 데모 H2는 영향 없음.
- 1단계 명세 (제안):
  - `V1__create_work_record.sql`: 회원 계정 (구글 식별자, 표시 이메일), 고용주, 정규 근무 기간 (시작일, 종료일, 제외 구간), F2 판정 스냅샷 컬럼.
  - `V2__create_work_day.sql`: 일한 날 (날짜, 행별 W 스냅샷), 근무 (날짜에 속한 고용주 + 시간), 기준 W 변경 이력.
- 2단계 테이블 (F3 추출 값과 체크리스트, F4 출력 기록, 시드 DB 테이블 등)은 `V3__` 이후로 추가한다.
- 승인 범위 밖의 스키마 작업은 하지 않는다.
