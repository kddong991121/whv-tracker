# F1 근무 기록과 인정 일수 (v4 반영)

## 바뀐 것 (2026-11-10)
- **하루 여러 근무**: 같은 날짜에 다른 일터의 근무를 각각 저장할 수 있다. 같은 일터는 날짜당 1건이다.
  - 같은 날짜 근무 시간 합계가 24시간을 넘으면 거부한다.
- **평소 하루 근무 시간**: 일터(`work_record.normal_hours`, Flyway V4)마다 둔다. 일한 날 기록 일터는 필수다.
- **하루 판정** (`WorkCalculator.summarize`):
  - 그 날 근무 중 하나라도 평소 시간 이상 → 인정 1일 (× 7 ÷ W).
  - 모든 근무가 평소보다 짧음 → **짧게 일한 날**. 합계와 기간(span)에 넣지 않고 개수만 센다 (`VisaSummary.shortDays`).
  - 두 곳 시간을 합쳐야 평소 시간이 되는 날도 짧게 일한 날이다 (PRD 4.2.3, 원문에 합산 기준 없음).
- **홈 표시**: `VisaSummary.displayDays()` = 인정 일수 합계를 정수로 내림 (58.8 → 58). `remainingDays()` = 목표까지 남은 일수.
- 근무 시간은 필수다. 재해 복구 봉사만 생략할 수 있다 (봉사는 시간과 무관하게 1일).

## 그대로인 것
- 정규 근무 기간(모드 A) 달력일 계산, 무급 날씨 휴무 차감, 2019-07-01 기준, 기록별 상한, W 변경 사유 규칙.
- 계정 단위 조회·저장 (`owner_user_id`).

## 핵심 코드 설명 (면접 대비)
- 날짜별로 묶는 이유: "하루는 1일을 넘지 않는다"는 원문 규칙이 고용주 단위가 아니라 **날짜 단위**이기 때문이다.
  그래서 계산기는 모든 일터의 근무 행을 날짜 기준 `Map<LocalDate, ...>`로 모은 뒤 날짜마다 한 번만 판정한다.
- 인정 판정은 저장 시점이 아니라 **조회 시점**에 한다 (`LedgerService.isFull`). 평소 시간을 나중에 고쳐도 다시 계산된다.
- 내부 값은 반올림하지 않고 `BigDecimal`로 들고 있다가, 화면에서만 내림·반올림한다. 7 ÷ 5 같은 나눗셈 오차를 줄이기 위해서다.

## 테스트 (필수)
- 계산: 한 근무라도 평소 이상이면 인정 1일, 짧은 근무만 있으면 짧게 일한 날, 정수 내림 표시.
- 저장: 같은 일터 같은 날짜 거부, 다른 일터 같은 날짜 허용, 하루 합계 24시간 초과 거부, 근무 시간 필수.

## 남은 것
- 화면은 아직 기존 `/ledger` 화면에 입력칸만 추가한 상태다. 시안(docs/design/) 기준 화면은 화면 단계에서 다시 만든다.
- 정규 근무/일한 날 화면 용어 교체 (PRD 4.7)는 화면 단계에서 한다.
- 로컬 MySQL에 이미 있던 일한 날 기록은 `normal_hours`가 비어 있어 모두 짧게 일한 날로 보인다. 배포 전이라 데이터 이관은 하지 않는다.
