# F3 페이슬립 가져오기와 증빙 체크리스트

## 만든 것 (2026-11-10)
- 화면 `/payslip` (하단 메뉴 "페이슬립").
  1. PDF 고르기 → **브라우저에서만** pdf.js로 글자를 읽는다. 파일 입력칸은 `name`이 없고 폼 밖에 있어서 서버로 가지 않는다.
  2. 고용주, ABN, 급여 기간, 총 근무 시간, 고용 형태(참고용)를 자동으로 채운다. 사용자가 확인하고 고친다.
  3. 급여 기간의 날짜 칸이 나오고 (평일 기본 선택), 일한 날을 고른다. 총 시간을 고른 날 수로 똑같이 나눠 넣는다.
  4. 증빙 체크리스트 7개 (선택), 현금 지급 체크 (선택), 저장 동의 (필수) → 저장.
- 서버 (`PayslipService.importPayslip`)는 읽은 값만 받아 `payslip` 테이블(Flyway V7)에 저장하고, 고른 날짜마다 일한 날 근무를 만든다.
  - 하나라도 실패하면 (같은 날짜 중복, 하루 24시간 초과 등) 트랜잭션으로 전부 되돌린다.
  - ABN은 선택이며, 넣으면 체크섬을 검사한다 (입력 검증, 규정 요건 아님).
- pdf.js는 CDN이 아니라 Maven 의존성 `org.webjars.npm:pdfjs-dist:5.7.284`로 앱 안에서 제공한다 (`/webjars/...`). 제3자 서버로 요청이 가지 않는다.
- 사진(JPG·PNG) PDF나 글자가 없는 PDF는 "글자를 읽지 못했어요" 안내 후 직접 입력한다.

## 읽는 규칙 (화면 스크립트 `parse`)
- ABN: `ABN` 뒤 숫자 11자리. 고용주: ABN 줄 앞 글자 또는 바로 윗줄, 없으면 첫 줄.
- 급여 기간: `dd/mm/yyyy - dd/mm/yyyy` (호주 표기, `to`·`–`도 허용).
- 총 근무 시간: `Total Hours`, `Hours Worked`, `Ordinary Hours` 뒤 숫자.
- 고용 형태: Casual / Full-time / Part-time.
- 페이슬립 양식이 회사마다 달라서 자동 입력은 "제안"이고, 저장 전에 사용자가 꼭 확인한다.

## 핵심 코드 설명 (면접 대비)
- 개인정보 최소 수집: TFN·계좌번호가 있는 원본을 서버에 두지 않으려고 파싱을 클라이언트로 옮겼다. 서버 코드에 multipart 업로드가 없다.
- 여러 근무 행을 한 트랜잭션에서 만들고, 중간에 예외가 나면 롤백되어 "반쯤 저장된" 상태가 생기지 않는다.

## 테스트 (필수)
- 저장 시 근무 행 생성과 시간 균등 분배 (30.5시간 ÷ 4일 = 7.63), 동의 필수, 기간 밖 날짜 거부, ABN 체크섬, 중복 날짜 시 전체 롤백, 화면에 업로드 필드 없음.
- 실제 Chrome에서 예시 PDF로 자동 입력 확인 (고용주, ABN, 기간, 시간, 고용 형태).

## 남은 것
- 저장한 페이슬립 수정·삭제.
- 사진 페이슬립 자동 읽기 (OCR)는 MVP 밖.

## 수정: 고용주 이름을 주소 줄로 읽던 문제 (2026-11-12, 실사용 페이슬립)
- 증상: "PAID BY / A & Z FOODS / PO BOX 6600 / CLIFFORD GARDENS QLD 4350 / ABN ..." 형식에서 고용주가 "CLIFFORD GARDENS QLD 4350"으로 채워졌다. 기존 규칙이 "ABN 바로 윗줄 = 고용주"였기 때문.
- 고침:
  1. "PAID BY", "Employer", "Business name", "Company" 제목의 다음 줄(또는 같은 줄 콜론 뒤)을 먼저 쓴다.
  2. 없으면 ABN 줄에서 위로 최대 5줄까지 올라가며 주소가 아닌 첫 줄을 쓴다. 주소 판단: PO BOX, "주 약자 + 4자리 포스트코드", 숫자로 시작(번지), Unit/Level/Floor/Suite/Shop으로 시작.
  3. 시간 값의 끝자리 0을 정리한다 (25.1000 → 25.1).
- 확인: 실제 페이슬립 PDF를 데모 화면에 올려 브라우저(pdf.js)로 읽힌 값을 확인했다 → 고용주 A & Z FOODS, ABN 99659169829, 기간 2025-07-28 ~ 2025-08-03, 시간 25.1, Casual. 원본 파일은 저장소에 넣지 않았다 (개인정보).

## 수정 2: 실제 페이슬립 4종으로 읽기 규칙 보강 (2026-11-12)
사용자가 서로 다른 회사 페이슬립 4장을 제공했다 (확인 후 바로 삭제, 저장소에 넣지 않음). 결과:

| 형식 | 고용주 | 기간 | 시간 | 고친 점 |
|---|---|---|---|---|
| "PAID BY" 형식 (A & Z FOODS) | ✓ | ✓ | 25.1 ✓ | 제목 다음 줄을 고용주로 |
| Rugby Employment (Ordinary 줄 2개) | ✓ | ✓ | 18.75 + 2.42 = 21.17 ✓ | "Employer Superannuation"을 제목으로 오인 → 콜론/단독 제목만 인정. 시급(29.33)을 시간으로 읽던 문제 |
| Roverworth (Paid From/To, 월 이름 날짜) | "Roverworth P4 4" (뒤 코드는 사용자가 지움) | ✓ | Total Hours 42.08 ✓ | 06-DEC-2024 같은 월 이름 날짜 |
| JBS Australia (Payment Advice) | ✓ | ✓ | 31 ✓ | "14011062338 ABN"처럼 뒤바뀐 ABN, 기간 대신 지급일을 잡던 문제 |

핵심 원인: pdf.js는 PDF 안의 글자를 **표 순서가 아니라 저장된 순서**로 돌려준다. 그래서 "Ordinary 549.94 18.75 29.3300 Hours"처럼 금액·시간·시급이 섞이고, 제목("Pay Period")이 값 뒤에 오기도 한다.

바꾼 규칙:
- **시간:** 줄 안에서 `시간 × 시급 ≈ 금액`(오차 2센트)이 되는 숫자 짝을 찾는다. 소수 자리가 많거나 `$`가 붙은 쪽이 시급이다. 짝이 없으면 "hours" 앞뒤 숫자를 쓴다. "Total Hours"가 있으면 그것을 먼저 쓴다.
- **기간:** "Pay Period" 제목 위치에서 가장 가까운 날짜 두 개를 고른다(순서 무관). 31일 이내여야 한다. 없으면 "Paid From/To" 각각 가장 가까운 날짜, 그다음 "A - B" 꼴.
- **고용주:** 제목(콜론이 있거나 단독) → 위쪽 15줄의 회사 이름 꼴(Pty Ltd, Limited, Ltd, Inc. 연금 회사 줄은 제외) → ABN 주변 순서로 찾는다.
- **날짜:** dd/mm/yyyy와 06-DEC-2024, 11 Nov 2024 같은 월 이름 표기를 모두 읽는다.

면접 포인트: 형식이 제각각인 비정형 문서에서 위치(좌표·순서)에 기대지 않고 **값 사이의 관계(시간×시급=금액)**와 **거리(제목에서 가장 가까운 값)**로 추출하면, 처음 보는 형식에도 잘 버틴다.
