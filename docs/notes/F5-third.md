## 바뀐 것

- **설정 "지금 준비 중인 비자"** (내 계정 화면 맨 위 카드, 홈 머리말의 "바꾸기" 링크로 이동)
  - 세컨 비자 (88일) / 서드 비자 (179일) 중 하나를 고른다. 기본은 세컨.
  - Flyway V8 `users.goal_visa INT NOT NULL DEFAULT 2`. 이미 가입한 사용자는 자동으로 세컨이다.
  - `POST /account/goal-visa` (로그인 + CSRF 필요). 2·3이 아니면 거부한다.
- **고른 비자에 따라 바뀌는 곳**
  - 홈: "서드 비자 준비 중", "N일 / 179일", "6개월(179일)이 지나야…", 달력과 일한 곳에는 서드 기록만 보인다.
  - 근무 기록: 서드에 넣은 일터만 보인다. 새 일터는 서드(3)로 저장되고, 폼에 "이 일터는 서드 비자 기록에 들어가요"라는 안내가 뜬다.
  - 전체 기록: 만료일 칸 이름이 "2년차 비자 만료일 (서드 준비 중)"으로 바뀌고, 페이스 계산 목표가 179가 된다. 일터 추가 폼의 차수 기본값도 서드가 된다. 세컨·서드 누적은 둘 다 그대로 보인다.

```
users.goal_visa ─┬─ 2 ─▶ summaries[0] (세컨, 88)  ─┐
                 └─ 3 ─▶ summaries[1] (서드, 179) ─┼─▶ 홈 숫자·문구 / PacePlan.of(...)
                                                    ├─▶ ledger.calendar(owner, month, goal)
                                                    └─▶ /work 일터 목록 필터, 새 일터 visaYear
```

## 핵심 코드 설명 (면접 대비)

1. **계산 클래스는 고치지 않았다.** `PacePlan.of(만료일, 여유일, 오늘, VisaSummary)`는 처음부터 `summary.target()`(88 또는 179)을 썼다. 그래서 어떤 비자의 누적을 넘기느냐만 바꾸면 됐다. 계산을 순수 함수로 분리해 둔 덕분에, 확장할 때 컨트롤러 한 줄만 고쳤다.
2. **화면 문구를 한 곳에서 만든다.** `VisaSummary.visaName()`은 "세컨"/"서드"를, `periodText()`는 "3개월(88일)"/"6개월(179일)"을 돌려준다. 템플릿이 숫자 88을 직접 쓰지 않게 했다.
3. **자동 전환은 하지 않는다.** 88일을 채워도 아직 1년차 비자일 수 있다. 앱이 비자 상태를 알 수 없으니 사용자가 고르게 했다.
4. **기존 데이터를 보존한다.** 저장된 기록의 차수(`work_record.visa_year`)는 건드리지 않는다. 설정은 무엇을 보여줄지만 정한다.

## 스스로 검토

- 보안: 새 POST는 로그인한 본인 계정만 바꾼다(`authentication.getName()` → 본인 users 행). CSRF 토큰도 필요하다.
- 마이그레이션: `DEFAULT 2`라서 기존 행이 깨지지 않는다. H2(테스트)와 MySQL 8 모두 지원하는 문법이다.
- 범위 밖 (결정 5): 2년차 비자 시작일 입력과 그 이전 근무 자동 제외는 하지 않았다.

## 추가: "일주일에 출근할 날"로 표시 (2026-11-11, 사용자 승인)

- 문제: "주 35.8일"처럼 불가능한 숫자가 나왔고, "주 2.7일"은 인정 일수라 실제 출근일과 달라 헷갈렸다.
- 바꾼 것:
  - `PacePlan.workDaysPerWeek()` = ⌈N × 5 ÷ R⌉. 날짜별 근무는 출근 5일을 인정 7일로 쳐주므로, 인정 주 W일 = 출근 W × 5/7일이다.
  - `achievable()`은 N ≤ R일 때 true. 하루에 인정 일수는 최대 1일이라 N > R이면 매일 일해도 못 채운다. 이때는 숫자 대신 "채우기 어려워요 · 최소 ⌈N/7⌉주"를 보여준다.
  - 홈: "6월 24일까지 끝내려면 / 주 4일 출근 / 하루 평소 근무 시간을 꽉 채운 날 기준이에요".
  - 홈 만료일 카드에 "만료일·여유 일수 수정" 링크를 넣었다 (`/ledger#visa-plan`).
- 시간 단위("주 16시간")를 쓰지 않은 이유: 규정은 날로 센다. 하루를 꽉 채우지 못한 날은 인정되지 않으므로, 시간으로 보여주면 "매일 2시간만 일해도 된다"로 잘못 읽힌다.
- 테스트: `PacePlanTest.workDaysPerWeek_andNotAchievable` (30일/70일 → 3일 올림, 87일/17일 → 불가능·13주). 전체 99개 통과.
